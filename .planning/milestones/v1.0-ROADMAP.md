# Roadmap: DAMP Agro Platform Roles & Access Control

## Overview

This roadmap defines the implementation path for adding dual-level role-based access control (RBAC) to DAMP Agro. The work progresses from database schema update (Prisma), through NestJS backend guards and service layer endpoints, to Next.js frontend UI integration and role-based route protection.

## Phases

- [x] **Phase 1: Database Schema & Role Link Layer** - Update Prisma schema with GlobalRole enum and Role model relations on FarmUser.
- [x] **Phase 2: NestJS Authorization Infrastructure** - Implement `@GlobalRoles()` and `@RequireFarmRole()` decorators along with `GlobalRolesGuard` and `FarmRoleGuard`.
- [x] **Phase 3: Role Management API Endpoints** - Build backend endpoints for Super Admin user role management and Farm Admin sub-user delegation and querying.
- [x] **Phase 4: Next.js Frontend Role & UI Integration** - Protect Next.js routes and build the Farm Sub-user Administration UI with role-based component rendering.

## Phase Details

### Phase 1: Database Schema & Role Link Layer

**Goal**: Update local database models with Prisma migrations for dual-level roles.
**Depends on**: Nothing (first phase)
**Requirements**: SCHEMA-01, SCHEMA-02, SCHEMA-03
**Success Criteria** (what must be TRUE):

  1. `User` table has `global_role` column (`SUPER_ADMIN`, `USER`).
  2. `FarmUser` table links `farmId`, `userId`, and `roleId`.
  3. `pnpm prisma validate` and `pnpm prisma generate` run cleanly.

**Plans**: 1 plan

Plans:

- [x] 01-01: Update Prisma schema and execute database migrations.

### Phase 2: NestJS Authorization Infrastructure

**Goal**: Create reusable NestJS guards and decorators for validating global claims and farm-level access.
**Depends on**: Phase 1
**Requirements**: AUTHZ-01, AUTHZ-02, AUTHZ-03, AUTHZ-04
**Success Criteria** (what must be TRUE):

  1. `GlobalRolesGuard` blocks non-SUPER_ADMIN users from global platform endpoints.
  2. `FarmRoleGuard` inspects incoming `farmId` and validates sub-user role (`ADMIN`, `OPERATOR`, `VIEWER`) in `FarmUser`.
  3. `SUPER_ADMIN` users bypass farm membership checks automatically via `SuperAdminGuard`.

**Plans**: 1 plan

Plans:

- [x] 02-01: Create roles decorators, GlobalRolesGuard, and FarmRoleGuard in NestJS auth module.

### Phase 3: Role Management API Endpoints

**Goal**: Provide REST endpoints for Super Admins and Farm Admins to assign, update, and query user roles.
**Depends on**: Phase 2
**Requirements**: ADMIN-01, ADMIN-02, ADMIN-03, ADMIN-04
**Success Criteria** (what must be TRUE):

  1. Super Admin can query and update global roles of platform users (`PATCH /api/admin/users`).
  2. Farm Admin can invite a sub-user and assign a farm role (`POST /api/farms/:farmId/users`).
  3. Farm Admin can view, edit, or remove sub-users from their farm.

**Plans**: 1 plan

Plans:

- [x] 03-01: Implement administrative user controllers and services in NestJS backend.

### Phase 4: Next.js Frontend Role & UI Integration

**Goal**: Integrate role protection into Next.js middleware, layout, and build the Farm Sub-user management UI.
**Depends on**: Phase 3
**Requirements**: UI-01, UI-02, UI-03, UI-04
**Success Criteria** (what must be TRUE):

  1. Next.js middleware redirects non-SUPER_ADMIN users attempting to access `/admin`.
  2. Farm dashboard displays a "Usuarios y Permisos" management panel for Farm Admins.
  3. Buttons for sensitive farm operations (e.g. creating animals, modifying geofences) are hidden or disabled for `VIEWER` roles.

**Plans**: 1 plan

Plans:

- [x] 04-01: Update Next.js middleware, API proxy, and build sub-user management components.

# Requirements: DAMP Agro Platform Roles & Access Control

**Defined:** 2026-08-11
**Core Value:** Real-time precision livestock monitoring and GIS geofence management with secure multi-tenant farm access control.

## v1 Requirements

### Database Schema & Audit

- [x] **SCHEMA-01**: Prisma schema updated with `GlobalRole` enum (`SUPER_ADMIN`, `USER`) on `User` model.
- [x] **SCHEMA-02**: Prisma schema updated with `Role` relation on `FarmUser` model (`roleId` link).
- [x] **SCHEMA-03**: Prisma migrations generated and applied to local PostGIS database (`pnpm prisma migrate dev`).

### Backend Authorization (NestJS)

- [x] **AUTHZ-01**: `GlobalRolesGuard` created in NestJS to validate `SUPER_ADMIN` / `USER` claims from Clerk JWT tokens.
- [x] **AUTHZ-02**: `FarmRoleGuard` created in NestJS to validate user membership and role (`ADMIN`, `OPERATOR`, `VIEWER`) in `FarmUser` for farm-scoped endpoints (`/farms/:farmId/...`).
- [x] **AUTHZ-03**: `@GlobalRoles()` and `@RequireFarmRole()` decorators implemented for controller route annotations.
- [x] **AUTHZ-04**: `SuperAdminGuard` override allowing `SUPER_ADMIN` global users seamless access across all farm endpoints.

### User & Role Administration API (NestJS)

- [x] **ADMIN-01**: Backend API endpoint for Super Admins to list, inspect, and update global user roles (`GET/PATCH /api/admin/users`).
- [x] **ADMIN-02**: Backend API endpoint for Farm Admins to invite and assign farm roles to sub-users (`POST /api/farms/:farmId/users`).
- [x] **ADMIN-03**: Backend API endpoint for Farm Admins to modify or revoke farm roles of existing sub-users (`PATCH/DELETE /api/farms/:farmId/users/:userId`).
- [x] **ADMIN-04**: Query endpoint to list farm sub-users and their assigned roles.

### Frontend UI Integration (Next.js)

- [x] **UI-01**: Next.js middleware and layout updated to restrict `/admin` platform routes to `SUPER_ADMIN` users.
- [x] **UI-02**: Farm management UI updated with a "Usuarios y Permisos" tab in farm dashboard.
- [x] **UI-03**: Interactive modal for Farm Admins to assign or change sub-user roles (`ADMIN`, `OPERATOR`, `VIEWER`).
- [x] **UI-04**: Conditional rendering of action buttons (create animal, edit zone, delete geofence) based on user's active farm role.

## v2 Requirements

### Fine-Grained Permissions & ABAC

- **ABAC-01**: Dynamic `RolePermission` mapping table in database allowing custom role definition per farm.
- **ABAC-02**: Granular action permissions (e.g. `VIEW_COSTS`, `EDIT_MEDICAL_EVENTS`, `TOGGLE_GEOFENCE`).

## Out of Scope

| Feature | Reason |
|---------|--------|
| Native Auth Replacement | Retaining Clerk for AuthN (JWT issuance, login UI). Replacing Clerk with native JWT is excluded. |
| Custom Permission Builder UI | UI editor for custom permission checkboxes is deferred to v2. |

# System Architecture

**Analysis Date:** 2026-08-11

## Architecture Overview

The **DAMP Agro** platform follows a decoupled, service-oriented architecture designed for precision livestock monitoring, GIS spatial management, and machine learning health predictions.

```
┌────────────────────────────────────────────────────────┐
│             Next.js Frontend (App Router)             │
│        (Leaflet GIS, Clerk Auth, Custom UI System)     │
└──────────────────────────┬─────────────────────────────┘
                           │ HTTP / REST API (Bearer JWT)
                           ▼
┌────────────────────────────────────────────────────────┐
│               NestJS Backend REST API                  │
│  (Controllers -> Services -> Prisma ORM -> PostgreSQL)  │
└──────────────┬───────────────────────────┬─────────────┘
               │                           │
               ▼ HTTP (REST)               ▼ SQL / PostGIS
┌─────────────────────────────┐ ┌─────────────────────────┐
│     FastAPI ML Service      │ │  PostgreSQL + PostGIS   │
│ (Health Anomaly Prediction) │ │ (Relational + Spatial)  │
└─────────────────────────────┘ └─────────────────────────┘
```

## Architectural Patterns

### 1. Modular Controller-Service-Repository Pattern (NestJS)

The NestJS backend (`/backend/src`) is divided into domain feature modules:
- **`AppModule` (`src/app.module.ts`)**: Core entry point importing sub-modules (`PrismaModule`, `AuthModule`, `FarmsModule`, `AnimalsModule`, `AnimalTypesModule`, `ZonesModule`, `IotModule`, `AlertsModule`, `WebhookModule`).
- **Controllers (`*.controller.ts`)**: Define HTTP routes, query parameters, DTO validation (`ValidationPipe`), and auth guards (`ClerkAuthGuard`).
- **Services (`*.service.ts`)**: Implement business logic, Prisma ORM operations, spatial geometry calculations, and external API calls.
- **DTOs (`dto/*.dto.ts`)**: Define request payloads with `class-validator` annotations (`@IsString`, `@IsNotEmpty`, `@IsEnum`, etc.).
- **Entities (`entities/*.entity.ts`)**: Represent output domain shapes.

### 2. Next.js App Router & Proxy Architecture (Frontend)

- **Route Groups**: Organized into `(auth)` for authentication pages and `(dashboard)` for application screens sharing layout/sidebar (`frontend/src/app/(dashboard)/layout.tsx`).
- **API Proxy Pattern**: Frontend Next.js API routes (`frontend/src/app/api/...`) act as client proxies forwarding requests to the NestJS backend API (`frontend/src/lib/proxy.ts`), forwarding authentication headers securely.
- **Data Fetching Hooks**: Custom React hooks (`useApi`, `useMutation` in `frontend/src/hooks/`) wrap fetch calls with loading state, error handling, and toast feedback.

### 3. Spatial GIS Engine & Geofencing

- **Prisma Native Spatial Types**: PostGIS polygon storage for `Sector` and `Geofence` models using `Unsupported("geometry(Polygon, 4326)")`.
- **Geofence Calculation**: `backend/src/iot/utils/geofencing.utils.ts` implements spatial point-in-polygon checks and boundary distance calculations (Haversine & Ray-casting algorithm) to detect escapes.

## Data Flow Pipeline

### IoT Telemetry & Alert Generation Flow

1. **Telemetry Ingestion**: Collar sends lat/lng & temperature payload to `POST /api/iot/telemetry`.
2. **Database Ingestion**: `IotService` creates a `TelemetryReading` record linked to the `Collar`.
3. **Spatial Geofence Check**: `IotService` checks if the telemetry point falls outside the animal's active `Geofence` via `geofencing.utils.ts`. If outside, an `ESCAPE` alert is recorded in the `Alert` table.
4. **ML Disease Prediction**: Telemetry window is forwarded to `http://ml-service:8000/predict/health`. If an anomaly is returned, a `HEALTH` alert is recorded.
5. **Dashboard Monitoring**: Frontend polling or refresh displays active alerts and live positions on the map (`LiveTrackingMap.tsx`).

# Technical Debt & Areas of Concern

**Analysis Date:** 2026-08-11

## Summary of Known Issues & Technical Debt

This document catalogs technical debt, security gaps, performance bottlenecks, and architectural fragile points identified across the codebase.

---

## High Priority Concerns

### 1. Database Schema Mapping Inconsistencies (`backend/prisma/schema.prisma`)
- **Issue**: There is a mix of singular and plural table names mapped via `@@map(...)` in `schema.prisma` (e.g. `@@map("users")` vs `@@map("farm")`, `@@map("role")`, `@@map("sector")`).
- **Risk**: Database migrations may cause confusion or table name collisions across different environments.
- **Recommendation**: Standardize table naming conventions across all Prisma models (either all plural or all singular).

### 2. ML Service Stub Implementation (`ml-service/main.py`)
- **Issue**: The machine learning microservice is currently running a rule-based stub engine (`FEVER_THRESHOLD = 39.5`, basic Haversine distance drift) rather than a trained scikit-learn/TensorFlow anomaly detection pipeline.
- **Impact**: Real-world biometric nuance (such as ambient weather temperature compensation or complex time-series movement patterns) is not yet captured.
- **Recommendation**: Train and serialize a machine learning model (`joblib` `.pkl` file) and load it in `ml-service/main.py`.

---

## Medium Priority Concerns

### 3. Spatial Queries & PostGIS Typing (`Prisma ORM`)
- **Issue**: Prisma models use `Unsupported("geometry(Polygon, 4326)")` for spatial columns.
- **Impact**: Prisma cannot generate native TypeScript types for geometry fields, requiring raw SQL queries or manual string parsing/formatting in `geofencing.utils.ts`.
- **Recommendation**: Utilize specialized PostGIS spatial query helpers or raw database queries (`prisma.$queryRaw`) with strict TypeScript DTO casting.

### 4. Clerk Auth Guard Error Handling & Environment Secret Fallbacks
- **Issue**: `ClerkAuthGuard` (`backend/src/auth/clerk-auth.guard.ts`) relies on `ConfigService.getOrThrow<string>('CLERK_SECRET_KEY')`. If `CLERK_SECRET_KEY` is omitted in development, NestJS startup fails immediately.
- **Recommendation**: Ensure local environment variable templates (`.env.example`) are present across `backend` and `frontend`.

---

## Low Priority / Operational Considerations

### 5. Port Allocation & Docker Compose Conflicts
- **Issue**: Local PostgreSQL container maps to port `5435:5432` (`docker-compose.yml`) to prevent conflicts with standard local PostgreSQL instances (5432).
- **Note**: Ensure `DATABASE_URL` in `backend/.env` targets port `5435` during local non-Docker development.

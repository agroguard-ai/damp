# Plan 06-01: Frontend Reusable Pagination Hook & UI Component

## Goal

Build a reusable, URL-synced frontend pagination solution in Next.js App Router featuring the `usePagination` React hook and a modern `PaginationControls` component.

## Tasks

<task>
<id>06-01-01</id>
<title>Create frontend pagination types and usePagination hook</title>
<read_first>
  - frontend/src/app/layout.tsx
</read_first>
<action>
Create `frontend/src/types/pagination.ts` and `frontend/src/hooks/usePagination.ts`.

In `pagination.ts`:
- Define `PaginationMeta` interface (`totalItems`, `page`, `limit`, `totalPages`, `hasNextPage`, `hasPrevPage`).
- Define `PaginatedResult<T>` interface (`data: T[]`, `meta: PaginationMeta`).
- Define `UsePaginationOptions` interface (`totalItems?: number`, `initialPage?: number`, `initialLimit?: number`, `syncUrl?: boolean`).

In `usePagination.ts`:
- Mark `'use client'`.
- Import `useSearchParams`, `usePathname`, `useRouter` from `'next/navigation'`.
- If `syncUrl` is true (default true), read `page` and `limit` from URL search params.
- Maintain state for `page` and `limit`.
- Implement `updateUrl(newPage: number, newLimit: number)` using `new URLSearchParams(searchParams)` and `router.push(pathname + '?' + params.toString(), { scroll: false })`.
- Provide helper methods: `goToPage(page: number)`, `nextPage()`, `prevPage()`, `setLimit(limit: number)`.
- Return object containing: `{ page, limit, totalPages, totalItems, hasNextPage, hasPrevPage, startIndex, endIndex, goToPage, nextPage, prevPage, setLimit }`.
</action>
<acceptance_criteria>
  - File `frontend/src/types/pagination.ts` exists and exports pagination interfaces.
  - File `frontend/src/hooks/usePagination.ts` exists and exports `usePagination`.
  - `usePagination` syncs `page` and `limit` to URL search params without page reload or scroll reset.
</acceptance_criteria>
</task>

<task>
<id>06-01-02</id>
<title>Build PaginationControls React component</title>
<read_first>
  - frontend/src/hooks/usePagination.ts
  - frontend/src/types/pagination.ts
</read_first>
<action>
Create `frontend/src/components/pagination/PaginationControls.tsx` and `frontend/src/components/pagination/index.ts`.

In `PaginationControls.tsx`:
- Mark `'use client'`.
- Accept props: `page: number`, `totalPages: number`, `totalItems?: number`, `limit: number`, `onPageChange: (page: number) => void`, `onLimitChange?: (limit: number) => void`, `limitOptions?: number[]` (default `[10, 25, 50, 100]`), `showItemRange?: boolean` (default `true`).
- Calculate range stats: `showingFrom = Math.min((page - 1) * limit + 1, totalItems)` and `showingTo = Math.min(page * limit, totalItems)`.
- Render range stats string: `Mostrando {showingFrom} - {showingTo} de {totalItems} resultados`.
- Render pagination controls:
  - Previous Page button (`<ChevronLeft />`, disabled if `page <= 1`).
  - Next Page button (`<ChevronRight />`, disabled if `page >= totalPages`).
  - Numeric page buttons with ellipsis truncation logic (e.g., `1 2 3 ... 10`).
  - Page limit selector dropdown (10, 25, 50, 100 items per page).
- Style with modern CSS / Tailwind utility classes fitting the DAMP Agro design aesthetic.

In `index.ts`:
- Re-export `PaginationControls` and `usePagination`.
</action>
<acceptance_criteria>
  - File `frontend/src/components/pagination/PaginationControls.tsx` exists and exports `PaginationControls`.
  - File `frontend/src/components/pagination/index.ts` re-exports hook and component.
  - `PaginationControls` renders range stats, Prev/Next buttons, page numbers, and limit selector properly.
</acceptance_criteria>
</task>

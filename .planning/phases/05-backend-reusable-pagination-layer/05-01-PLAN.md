# Plan 05-01: Backend Reusable Pagination Utilities

## Goal

Create a standardized, reusable pagination layer in NestJS backend (`backend/src/common/pagination/`) featuring a validated query DTO (`PaginationQueryDto`), a generic response metadata interface (`PaginatedResult<T>`), and a Prisma model `paginate()` helper with full unit test coverage.

## Tasks

<task>
<id>05-01-01</id>
<title>Create PaginationQueryDto and PaginatedResult interface</title>
<read_first>
  - backend/src/app.module.ts
</read_first>
<action>
Create `backend/src/common/pagination/dto/pagination-query.dto.ts` and `backend/src/common/pagination/interfaces/paginated-result.interface.ts`.

In `pagination-query.dto.ts`:
- Define `PaginationQueryDto` class.
- Use `@Type(() => Number)` from `class-transformer` for `page` and `limit`.
- Use `@IsOptional()`, `@IsInt()`, `@Min(1)` for `page` (default 1).
- Use `@IsOptional()`, `@IsInt()`, `@Min(1)`, `@Max(100)` for `limit` (default 10).
- Use `@IsOptional()`, `@IsString()` for `sortBy`.
- Use `@IsOptional()`, `@IsIn(['ASC', 'DESC', 'asc', 'desc'])` for `sortOrder` (default 'DESC').

In `paginated-result.interface.ts`:
- Export `PaginationMeta` interface with fields: `totalItems: number`, `page: number`, `limit: number`, `totalPages: number`, `hasNextPage: boolean`, `hasPrevPage: boolean`.
- Export generic `PaginatedResult<T>` interface containing `data: T[]` and `meta: PaginationMeta`.
</action>
<acceptance_criteria>
  - File `backend/src/common/pagination/dto/pagination-query.dto.ts` exists and exports `PaginationQueryDto`.
  - File `backend/src/common/pagination/interfaces/paginated-result.interface.ts` exists and exports `PaginationMeta` and `PaginatedResult<T>`.
  - `PaginationQueryDto` correctly transforms string inputs to numbers and clamps/validates `page` and `limit`.
</acceptance_criteria>
</task>

<task>
<id>05-01-02</id>
<title>Implement Prisma paginate() helper and unit tests</title>
<read_first>
  - backend/src/prisma/prisma.service.ts
  - backend/src/common/pagination/dto/pagination-query.dto.ts
  - backend/src/common/pagination/interfaces/paginated-result.interface.ts
</read_first>
<action>
Create `backend/src/common/pagination/pagination.helper.ts`, `backend/src/common/pagination/pagination.helper.spec.ts`, and `backend/src/common/pagination/index.ts`.

In `pagination.helper.ts`:
- Export `paginate<T, K>(modelDelegate: { findMany: Function; count: Function }, queryDto: PaginationQueryDto, findManyArgs?: K): Promise<PaginatedResult<T>>`.
- Calculate `page = Number(queryDto.page) || 1` and `limit = Number(queryDto.limit) || 10`.
- Calculate `skip = (page - 1) * limit`.
- Run `Promise.all([ modelDelegate.findMany({ ...findManyArgs, skip, take: limit }), modelDelegate.count({ where: findManyArgs?.where }) ])` concurrently.
- Compute `totalPages = Math.ceil(totalItems / limit)` (0 if `totalItems === 0`).
- Return `data` and `meta` (`totalItems`, `page`, `limit`, `totalPages`, `hasNextPage: page < totalPages`, `hasPrevPage: page > 1`).

In `pagination.helper.spec.ts`:
- Write unit tests verifying:
  1. Standard pagination calculation (page 1 of 2, page 2 of 2).
  2. Empty dataset handling (`totalItems = 0`).
  3. Correct calculation of `skip`, `take`, `hasNextPage`, `hasPrevPage`.

In `index.ts`:
- Re-export `PaginationQueryDto`, `PaginatedResult`, `PaginationMeta`, and `paginate`.
</action>
<acceptance_criteria>

  - File `backend/src/common/pagination/index.ts` re-exports all pagination utilities.
</acceptance_criteria>
</task>
